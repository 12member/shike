# 食刻 · 网页版

拍照/说一句记下这餐吃了什么，算碳水、蛋白、脂肪和热量，再按你的身高体重给建议。

> ### 🚀 在线使用
> 直接打开即可用，无需下载、无需安装：
>
> **https://12member.github.io/shike/**
>
> 当前项目以**网页端**为主，小程序版已暂停维护。

---

## 一、怎么跑起来

### 最快：直接打开

双击 `index.html`。全部功能可用（除了拍照自动识别，见第三节）。

### 推荐：起个本地服务

```bash
node server.js
```

然后打开 http://localhost:5178

用 `file://` 直接打开也能用，但某些浏览器会限制 `localStorage`，记录可能存不住，所以建议走这个方式。

### 要拍照自动识别：带上模型配置启动

```bash
VISION_API_URL=https://api.hunyuan.cloud.tencent.com/v1/chat/completions \
VISION_API_KEY=sk-你的key \
VISION_MODEL=hunyuan-vision \
node server.js
```

PowerShell：

```powershell
$env:VISION_API_URL="https://api.hunyuan.cloud.tencent.com/v1/chat/completions"
$env:VISION_API_KEY="sk-你的key"
$env:VISION_MODEL="hunyuan-vision"
node server.js
```

Key 只在服务端，浏览器看不到。这是网页版必须有个小后端的原因——把 Key 写进前端 JS 等于公开。

**零依赖，不用 `npm install`。**

## 二、关于旧的小程序版

本项目现在**以网页端为主**，小程序版已暂停维护，不再作为交付重点。

网页版的营养计算引擎（`js/engine.js`）最初是从小程序 `utils/` 目录打包而来，两者同源：

| | 旧小程序版（已暂停） | 网页版（当前主线） |
|---|---|---|
| 计算逻辑 | `shike-miniprogram/utils/*.js` | **同一份**，打包成 `js/engine.js` |
| 数据存储 | `wx.setStorageSync` | `localStorage` |
| 识别请求 | 云函数 + 环境变量 | `server.js` + 环境变量 |
| 上线门槛 | AppID、类目、隐私指引、审核 | 静态托管即可，发链接就能用 |
| 安装 | 微信里搜 | 浏览器打开，可加到主屏幕 |

`js/engine.js` 是**生成文件，不要手改**。需要更新营养计算、食物库、运动库、建议规则时，直接改引擎源文件后重新生成：

```bash
node build.js
```

这样营养计算只有一份，不会两边算出的数不一样。

## 三、没有识别服务时，能用到什么

全部功能，除了「拍一张自动认菜」：

- **说一句**：本地词典拆解，118 条食物 + 135 条口语别名，支持「一碗牛肉面加个卤蛋」这类说法，也支持直接写克数
- **手动选**：7 个分类、搜索、按默认分量加入，可逐项调克数，营养值实时重算
- **运动记录**：32 项运动按 MET 公式算消耗，给出练后补充建议
- **个人方案**：BMI（中国标准）、BMR（Mifflin-St Jeor，展示代入过程）、TDEE、每日热量目标、三大营养素克数
- **营养诊断**：蛋白缺口、油偏多、蔬菜不足、热量超支、运动日吃太少，建议里的食物能一键加进记录
- **历史**：近 7 天柱状图 + 明细

拍照识别只是锦上添花，不是必需品。这也是它能在没后端的情况下完整跑起来的原因。

## 四、目录

```
shike-web/
├── index.html          页面骨架
├── css/style.css       全部样式
├── js/engine.js        ← 自动生成的计算引擎（勿改），改源后 node build.js 重新生成
├── js/app.js           界面与交互
├── build.js            打包引擎：node build.js
├── server.js           静态服务 + 识别接口代理（零依赖）
├── test.js             冒烟测试：node test.js（假 DOM，跑完整交互链）
└── README.md
```

`node test.js` 会把建档 → 记餐 → 改分量 → 记运动 → 练后加餐 → 历史 → 删除 → 清空
整条链路跑一遍，改完代码可以用它确认没弄坏东西。

## 五、想放到公网上

三种方式，按省事程度排：

1. **静态托管**（Vercel / Netlify / Cloudflare Pages / 对象存储）
   把整个目录传上去即可。但没有识别服务，拍照那一栏会提示未配置。

2. **任意能跑 Node 的服务器**
   `node server.js`，前面挂个 Nginx。这样拍照识别能用，Key 也在服务端。
   国内服务器需要域名备案；只想自己用可以不备案，直接用 IP + 端口。

3. **想让别人也能用**
   网页版的好处是没有主体和类目限制、不用等平台审核。但如果要收钱、要采集用户数据，
   该有的隐私政策还是要有。

## 六、几个实现上的取舍

**为什么不用框架**
整个站没有依赖，`index.html` + 一个 CSS + 一个 JS。首屏几百 KB，任何静态托管都能放，十年后也不会因为框架版本跑不起来。

**为什么照片要压缩再发**
手机原图 5MB，转 base64 后 6.7MB，光上传就要好几秒。压到 1024px / JPEG 0.82 之后一般 150KB 左右，识别精度几乎不受影响。

**为什么运动消耗不用手环的数**
手环普遍比公式值高 30%~50%。拿虚高的数字去「奖励」自己多吃，是最常见的减不下来原因。这里用 `MET × 体重 × 小时`。

**为什么克数能改**
照片和文字估分量的误差本来就有 ±20%~30%。让用户改一下、营养值实时重算，比假装精准有用。
