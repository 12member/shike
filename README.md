# 食刻

拍一张、说一句，就把这餐的碳水和热量记清楚。

一个纯网页的饮食记录工具：拍照或写一句话记下这餐，自动估算热量与碳水、蛋白质、脂肪，
再结合你的身高体重给出每日参考目标和补充建议。运动消耗也能一并计入。

> ### 在线使用
> **https://12member.github.io/shike/**
>
> 电脑和手机浏览器都能打开，无需下载安装。数据保存在你自己的浏览器本地，不上传服务器。

## 功能

- **拍照记餐**：调用摄像头或从相册选图，识别出食物种类和大致分量，逐项可改克数
- **说一句**：写「一碗牛肉面加个卤蛋」，自动拆成食物条目并估分量，没配识别服务时走内置词典
- **手动选**：7 个分类、搜索、按默认分量加入，营养值实时重算
- **运动记录**：32 项运动按 MET 公式算消耗，给出练后补充建议，可一键加入当天记录
- **个人方案**：BMI（中国标准）、BMR（Mifflin-St Jeor，展示代入过程）、TDEE、每日热量目标、三大营养素克数
- **营养诊断**：蛋白缺口、油偏多、蔬菜不足、热量超支、运动日吃太少，建议里的食物能直接加进记录
- **历史**：近 7 天柱状图 + 每日明细

## 本地运行

```bash
node server.js
```

打开 http://localhost:5178

零依赖，不用 `npm install`。直接双击 `index.html` 也能用，但部分浏览器会限制 `file://`
下的 `localStorage`，记录可能存不住，所以推荐起服务。

要启用拍照自动识别，带上模型配置启动：

```bash
VISION_API_URL=https://api.hunyuan.cloud.tencent.com/v1/chat/completions \
VISION_API_KEY=sk-你的key \
VISION_MODEL=hunyuan-vision \
node server.js
```

PowerShell：

```powershell
$env:VISION_API_URL="https://api.hunyuan.cloud.tencent.com/v1/chat/completions"
$env:VISION_API_KEY="sk-你的key"
$env:VISION_MODEL="hunyuan-vision"
node server.js
```

Key 只在服务端，浏览器看不到。这是需要一个小后端的原因——把 Key 写进前端 JS 等于公开。

**不配识别服务也能用**：文字走内置词典（118 条食物 + 135 条口语别名），其余功能完全不受影响。

## 部署

纯静态站点，`index.html` + `css/` + `js/` 直接托管即可，无需构建。

本仓库用 GitHub Pages 发布 `main` 分支根目录，线上地址见顶部。
`.nojekyll` 已就位，避免 Jekyll 处理下划线目录。

注意：静态托管下**拍照识别不可用**（它需要服务端转发模型请求）。
要在线上启用识别，把 `server.js` 部署到任意能跑 Node 的环境，或改用 Serverless Functions。

## 目录

```
├── index.html          页面骨架
├── css/style.css       全部样式（含响应式布局）
├── js/app.js           界面与交互
├── js/engine.js        打包产物，勿手改
├── engine/             计算引擎源码：营养计算、食物库、运动库、建议规则、本地存储
├── build.js            打包引擎：node build.js
├── server.js           静态服务 + 识别接口代理
├── test.js             冒烟测试：node test.js
└── docs/               界面截图
```

改了 `engine/` 里的源码后重新打包：

```bash
node build.js
```

`node test.js` 会把建档 → 记餐 → 改分量 → 记运动 → 练后加餐 → 历史 → 删除 → 清空
整条链路跑一遍，改完代码可以用它确认没弄坏东西。

## 数据存哪

全部保存在**浏览器 localStorage**，不上传任何服务器。
换设备、换浏览器、清理站点数据都会丢失记录，也没有云同步。

## 实现上的取舍

**为什么不用框架**
整个站没有依赖，`index.html` + 一个 CSS + 一个 JS。首屏几百 KB，任何静态托管都能放，
十年后也不会因为框架版本跑不起来。

**为什么照片要压缩再发**
手机原图 5MB，转 base64 后 6.7MB，光上传就要好几秒。压到 1024px / JPEG 0.82 之后一般
150KB 左右，识别精度几乎不受影响。

**为什么运动消耗不用手环的数**
手环普遍比公式值高 30%~50%。拿虚高的数字去「奖励」自己多吃，是最常见的减不下来原因。
这里用 `MET × 体重 × 小时`。

**为什么克数能改**
照片和文字估分量的误差本来就有 ±20%~30%。让用户改一下、营养值实时重算，比假装精准有用。
